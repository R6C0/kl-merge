## 0. Mechanism facts everything rests on
- All speech, stock or ours, ends in `0x421c70` (line, other, speaker, last) -> `0x578840` (queue) -> `0x7d0e80` (start sound) (KT:26-36, SPEC:13). Speech is 2D and global, with no network call anywhere in that chain (SPEC:31, SPEC:37). So stock netcode replicates NO speech. Each peer plays what its own rules code fires.
- Stock Arcade events call `0x58a070(group, other, speaker, x)` (SPEC:10). The group picks the line at random and a group repeats no sooner than 15 s (BOTS:100). Per-character lines use entry `K_C<n>`, where n-1 = `byte[rules+0x33e+slot]`, and that table exists only in the Arcade rules object `ZGameRulesHeist` (BOTS:125-131, KT:452-453). The online rules (Sv 0x3a8 / Cl 0x334 bytes) have no voice table (KT:452, KVO:81).
- Who speaks, per event (BOTS:147-162): per-character events use "P" (the slot the event concerns); driver/police/team lines use -2..-6 and have no per-character variant. That an AI heister's own pickup fires `jackpot` in its voice was NOT traced in the EXE (BOTS:164-166).
- An AI heister whose group name has no digit 1..9 at index 18 hits an int3 at 0x51ab2d when it speaks (BOTS:31-33, SPEC:84). That is why every online path passes explicit keys.

## 2. Missing pieces (what is concretely absent)
1. **OnlineVoiceByLook is off live** (not in INI), so no Dead Men voice on bot lines, and in the VB2 bench it never produced a leaf.
2. **No online bot banter.** The banter loop's online who holds humans only (KVO:69-75), so bots never idle-chat, pair-chat, or react to money/stage/down (KT:859-881) online. In Arcade every crew record is a member.
3. **No sync of banter.** KT:938 says nothing is sent. Both seats randomize independently (KT:195), so a client and host never hear the same exchange (scripted Kane/Lynch scenes use a local clock, KT:765-776).
4. **No event beyond loot+boarded** in BV (BV:12): no cash-majority, shoot-off-money, call-escape, van-damaged, level-bounds, hold-vehicle, traitor, revenge. These come from stock rules in Arcade (BOTS:150-162) and are not fired for bots online.
5. **Dead Men leaf for boarded** is impossible by design (YouEsc kept stock, BV:107).
6. **Remote-human voices** (a Dead Men body worn by another human) stay stock on each seat (KVO:6, `OnlineCrew` absent live).
7. **Police/driver lines for bot-triggered events** are not covered by any hook.

## Critique (adversarial pass, 2026-11-05, read-only; checked klbotvoice.c, klbotvoice_logic.h, klvoice_online.c, klonline_read.c, live ini, VB2_DM07/inst2 log)

Confirmed: items 1-2 (loot/boarded only, KLSYV), ini keys, the online who is humans-only (klvoice_online.c:69-75 loops `o.r`; bots live in `o->bot` with seat -1, klonline_read.c:262, so they cannot be members without new code), banter unsynced (kltalk.c:938), OnlineCrew absent from [Voice] (the ini line 134 `OnlineCrew=1` is [HUD]).

Corrections
1. D2 "packet needs no change" is WRONG. `KLBV_NEV` is 3 and decode/encode reject `ev >= 3` (klbotvoice_logic.h:36,50); the gap table is `[9][KLBV_NEV]`. New events need KLBV_NEV bumped (a new receiver on an old host is fine, an OLD receiver silently drops new ev: mixed-build safe, but the gap array size changes). Also `klbv_look_key`/`klbv_ev_name`/key-template index `ev==LOOT?0:1` (klbotvoice.c:97,128) treat every non-loot event as Escape: a new event would play the YouEsc key until that indexing is replaced. The claim that van call / van damage host sites "are already tracked in BF" is unverified (only the GRABBED lines BF:2313/2363 and phase-3 BF:1344 are known hook sites).
2. D3 "full key in the packet, ~64 B, < MTU" conflicts with the fixed `KLBV_LEN 20` layout (fields: T, seq, ev, digit, var, bytes 18-19 spare). It needs a NEW magic/length (e.g. `KLSYW`), not a `var` variant; `var` is validated 1..3 only. A key-id alternative needs identical KLTalk.ini on both seats: unproven.
3. Item 3 / D1 is misdiagnosed. In VB2_DM07/inst2 ByLook DID reach Dead Men names (Standen log:6688, Hutchison :10149, Red :10201): each gave `klk_say 0` = the level .LOC has no `KLVoice/<Name>/JackPot_01` leaf (leaf spelling is the GUESS at klbotvoice.c:101; `kl_dmvoice.py:65` maps `^JackPot` by regex, so real leaf names likely carry other suffixes). "Wardrobe name unreadable" appeared only for ch 6 and 7, plausibly Dog Days bodies (`kvo_name_of` false by design), so it is not a bug to fix. The blocker is DATA (leaf names/presence in the DM07 .LOC), not hook code. Enabling ByLook live now only adds a wasted klk_say + log line per loot event; it cannot change what is heard until leaves exist. Check the leaf list with tools/kl_loc.py before any ear test.
4. Gap row "combat callouts ... FA_ShootOffMoney seen on client (log:6285)" is the local banter pool (`dm_shoot_any`, "the player = record 1"), not a stock combat event; the doc mixes the two. Not evidence about stock online rules.
5. `-6` as speaker for a client with no crew record is flagged GUESS in code (klbotvoice.c:139) but the log shows `talk: said ...` and `klk_say 1` only; "said" is queue acceptance, not audibility. No log proves audible output; ear test is still owed for loot lines on a client.
6. Desync/spam risks missing from D2-D4: (a) a host `klbv_play(...,0)` ignores the gap while clients apply it (check_gap=1), so host and client can differ on dropped lines; (b) the 15 s gap state is per seat and reset on role/round, a late joiner misses events; (c) D4 moving human chatter to the host means a client with the host 150 ms+ away hears pair lines that name a speaker whose position/status the client sees differently (status 7 filtering uses the local read); (d) UDP broadcast 255.255.255.255 with 3x repeats per event: D2 with 4 events x 8 bots multiplies traffic and the 4-slot `pend[]` queue (klbotvoice.c:34) overflows ("send queue full") on bursts; (e) D5 enabling `[Voice] OnlineCrew` also changes kltalk/kltrait who (klvoice_online.c:12), not only voices.
7. Untested/unproven in the doc and left as GUESS: whether stock online rules fire any combat/cop/traitor lines (a log probe on 0x58a070 answers this; the doc's D6 is right to start there).
