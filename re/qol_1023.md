## What it does (klhook/klqol.c, `[QoL]`, every key defaults to the old behaviour)
Win32 only: no kl2.exe byte written, no game routine called. It reads session role/mode/state (the dwords kllobby.c reads).
| key | default | effect |
|---|---|---|
| FlashOnReady | 0 | taskbar button flashes (until the window is in front) when a load ended, when an FA lobby (type 4) enters state 0xd (start countdown), when the session reaches 0x28 (round over). Only while another program is in front. |
| LoadGapMs | 3000 | main-loop silence (500..60000) that counts as a finished load |
| BackgroundMs | 0 | 1..200 ms slept per game tick while another program is in front. Local sessions only (net role 0/1); a host or client is never slept |
| ReleaseCursor | 0 | ClipCursor(NULL) once when the game loses the foreground |
| Log | 1 | `qol:` log lines |

Why these: the owner waits through 60-120 s loads and the lobby countdown in another window (log notes on scripted vs human rounds, monitor-off runs, two-instance bench), with no cue when the game is ready; a backgrounded instance renders at full speed and can keep the mouse clipped. They are pure Win32 and need no engine research.
