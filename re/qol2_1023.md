# QoL round 2 (2026-10-23, branch feat/1023-qol2)

New file `klhook/klqol2.c` (prefix `kqb_`), included by klhook.c after klpm_arc.c; init `kqb_init`, tick `kqb_tick`.
klqol.c, klmusic.c, klambience.c, klbalance.c untouched. Built, NOT run in the game. All keys in `[QoL2]`, all default off.
No code byte of kl2.exe changes (anti-tamper safe). Log lines all start `qol2:`.

## What it does
1. Watchdog (`Watchdog=1`). Own clock per AI crew record (works with `[Bots] Restless=0`). A bot that moved <= WatchMoveCm
   for WatchStillSec, off its defend place (more than WatchMeantCm away), not downed / hurt in last 4 s / owned by klhop /
   on a vehicle stage, after WatchAfter s of round, on a non-stock level:
   step 1 = order given again (klescort `kle_order2`, same call as klmove branch b);
   step 2 = WatchTeleSec later, still standing: `klt_teleport` to (a) its defend place (<= WatchRangeCm, same floor),
   (b) else klhop `klv_free` landing place, (c) else nearest klmove cover place. Refused if a human is within WatchSeenCm,
   `klt_refuse` names a fault, or the bot is a human shield. Max WatchMax teleports per bot and round. `WatchDry=1` logs only.
2. Heister key (`HeisterKey=<VK>`, 72 = H). On the Arcade page (top window HeistModeMenu, read call-free) sends
   HeisterUps UP then HeisterDowns (5) DOWN taps with SendInput scan codes, 70 ms apart, dropped if the page closes.
   The real focus jump (ZWINDOWS SetFocus 0x7f09f0 with the button window from find 0x83faf0) is NOT done: ZWINDOWS has no
   static address in SHIP. Plan: one TEST-build probe to read the ZWINDOWS global, then SetFocus on the Heister element.
3. Mute when unfocused (`MuteBackground=1`, `MuteLevelPct`). Own thread, COM MTA, default render endpoint session
   `ISimpleAudioVolume`, polls 250 ms; restores a leftover muted volume at start.

## GUESS list
- node place `[actor+4]` is the bot position; byte `actor+0x64c` = downed; `klv_free` fits a carried bot.
- All times and distances (25/20 s, 3 m, 15 m, 60 m, 6 m) are tuning guesses.
- SendInput scan codes reach the game's DirectInput; focus is on the first button when the key is pressed; Heister is row 6.
- The game's sound goes through this process's default audio session.
- The window stack layout `+0x32c + 4*i` (i = 1..n, top last) is taken from klslot.c's kls_menu_watch; re-check on first run.

## Live test for the lead
1. Watchdog dry run first: ini `[QoL2] Watchdog=1 WatchDry=1 WatchStillSec=10 WatchTeleSec=5 WatchAfter=5`, `[Bots] Restless=0`.
   Arcade round on a graft map (F01 slot Subway graft or a DM map), 3+ bots. Expect `qol2: Watchdog=1 ...` at start.
   Wedge a bot (stand it against a prop / let one stick). Expect `watchdog: record N stood ... ORDER AGAIN would be given (dry run)`
   then `... WOULD be put on (...) - DRY RUN`. Then `WatchDry=0`: `ORDER AGAIN` then `TELEPORTED to (...)`. Bots waiting at gates give
   `a meant wait, left alone`; stock maps give `nobody is helped here`.
2. Heister key: `HeisterKey=72`, Arcade page, press H: `heister shortcut: ... 0 UP, then 5 DOWN taps`, `5 tap(s) sent`; the
   Heister button is focused if SendInput reaches DirectInput. If the log shows taps but nothing moves, GUESS 1 failed.
3. Mute: `MuteBackground=1`, alt-tab: `mute: game in the background - volume 100 % -> 0 %`, back: `volume back to 100 %`.
