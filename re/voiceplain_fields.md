# The 'plain' (flag-0) speech lines, settled from the exe and the files (2026-10-23, scheduled check-in)

Static reading of kl2.exe 0490 plus the stock .LOC files and the installed DM01 archive, nothing run in
the game. Tool: `tools/kl_voice_fields.py` (table + check + `plain <level|zip>`); table: `re/voice_fields.json`.
Reason: the 12:28 open item said the flag-0 lines (named: FA_YouEscaped*_R, police events) are never
swapped for a Dead Men body and "a shippable fix needs a data-side swap". This settles what those lines
ARE, and the answer closes the item.

## 1. How the exe makes the 302 lines (ZOnlineFragileAllianceSettings vtable slot 16 = kl2 0x88d780)
- For each of 302 string fields (member offsets 0x70 .. 0x538, one call site each; the list is
  `re/voice_fields.json`, regenerated by `python tools/kl_voice_fields.py table`) the Init calls
  `0x877a30(group, key, who, flag)` -> line appended to a GROUP (manager + g*0x18; 93 groups used, g16
  never; a group holds at most 3 lines, `cmp [group+4],3 / jge` drops the rest), or
  `0x6b8710(&slot, key, who, flag)` -> one of 27 SINGLE slots manager+0x8d0 .. +0x93c (0x8f8 never set).
- `flag` and `who` are IMMEDIATES at the call site (code). The KEY is the field's string (data).
  flag 1: ten entries K_C1..K_C9 + K_R_C9 (missing key = empty slot), line+0x20 = 1.
  flag 0: ONE entry for K itself; no such key -> the line is freed (NULL). 108 fields flag 1, 194 flag 0.
- `kl_voice.LINES` (field -> flag, who) agrees with every one of the 302 call sites (the tool's check:
  0 mismatches). New here: the GROUP of every field, and the 27 singles (klvoice.c walks 19,
  0x8d0..0x918; the other 8, 0x91c..0x93c = fields 315..323, and 0x8d0/0x8d4 = fields 311/312, are all
  flag 0, who -1 / 2: nothing the per-character swap could use, only [Voice] Plain never sees them).
- Field numbering: settings field = (offset - 0x2c) / 4 into the 340 values, as kl_voice has it. PROVEN
  on F02 and F07: with it 228 of the 228 non-empty line keys exist in the .LOC the way their flag looks
  them up (plain K for flag 0, K_C<n> for flag 1) and 0 the other way; one field earlier or later gives
  34 / 42 wrong-way hits. WARNING for anyone pairing the RTP record list to memory: kl_rtp's own-record
  order (record +0x10) puts 0x70 one field LATER than the truth here (my first table was off by one and
  produced a false "silent heister lines" story before the .LOC test caught it). Fields 155..159 are
  not lines (strings / ints between LevelBoundsPolice and the time warnings).

## 2. What the flag-0 fields hold (English texts; `kl_voice_fields.py plain`)
Stock F02: 126 flag-0 fields have a key the .LOC has, 0 are missing, 68 are empty. By speaker (read off
the text): the RADIO CONTACT (Glazer, the `_R_C9` keys: TeamLeading / Trailing / Draw / WinGame /
loseGame / OneMercLeft, AllDead, OneMinLeft / TwoMinleft / ThreeMinleft, TimeOut, MissionReminder ...),
the GETAWAY DRIVER (CallEscResponse "Easy... I'm almost there", LastEsc "this is your last chance",
Boarding "Get in! Get in!", BoardingEnd / BoardingEndInside "Too slow! Find another ride!",
DriverBribeAccept, HoldEscapeVehicle), the POLICE radio (every *Police* key, PoliceReward,
LevelBoundsPolice, TeamDeadPolice ...), the UNDERCOVER COP mode (UCC*), and exactly THREE heister
events recorded once for everybody: PersonalRevenge_01/02/03 (+ _R twins, groups g8 / g9: "Revenge has
never been so sweet", "[Cursing in chinese]...", "You ain't worth the air you breath") and
DirtyMoney_01/02/04 (g37: "I just love easy money", "Yeah. I can carry that", "No shame in a little
reward"). TeamAllianceReminder_01/02_R (g83) is the radio contact.
Installed DM01 (Dead Men keys in the grafted settings): 134 present, 0 missing, 60 empty. Same picture:
radio / driver / police / UCC, plus the three shared heister events with Dead Men's own single
recordings: FA_PersonalRevenge_01/03/05 (+_R), FA_DirtyMoney_01/02/05, and FA_Drop_Cash_01/02/03 (+_R;
groups g19 / g20, who -1, EMPTY on every stock Dog Days level: the engine has the drop-cash event, Dog
Days never voiced it). FA_YouEscaped01/02/03(_R) are FLAG-1 fields (g47 / g48) with all nine _C
variants in the .LOC (loc_aliases), Backstab / CashMajority / JackPot likewise: klvoice's per-body
swap already covers them. So the 12:28 note's "FA_YouEscaped*_R is a flag-0 line" was wrong.

## 3. Consequences (the item is closed, not open)
- A flag-0 line is ONE recording for every speaker by CODE. No level-file change can make it
  per-character: the only per-character path is a flag-1 field, and the three shared heister events
  (PersonalRevenge, DirtyMoney, DropCash) have NO flag-1 field - their groups g8 / g9 / g19 / g20 /
  g37 are flag 0 throughout. Stock Dog Days heisters share one actor there too. The "data-side swap"
  the 12:28 note asked for does not exist; what data CAN choose is which single recording plays (on
  the Dead Men maps it is already Dead Men's own merc line, e.g. "Finder's keepers...").
- The voiceplain `Plain=1` patch (hashed code, TEST + SessionSafe=0 only) would change the voice of
  exactly those 15 lines / 3 events. Not worth shipping or testing; keep it as the TEST probe it is.
  `PlayLog` keeps its value as the proof that the game plays the swapped flag-1 entries.
- Everything else a Dead Men body says in stock voice is NOT a heister line: radio contact, driver,
  police, UCC. Those should stay as they are (a Dead Men merc voice reading Glazer's lines would be
  wrong).
- klvoice.c's `KVO_SINGLES 19` misses 8 single slots (0x91c..0x93c) and the two at 0x8d0 / 0x8d4 are
  included; harmless (all flag 0). No code change needed.
- Rule for the authoring tools (kl_fa_author / kl_dmvoice / fill_lines): never put a key into a
  flag-0 field expecting it to follow the speaker; a Dead Men key there is fine as the shared line.
  `kl_voice_fields.groups()` gives field -> group for anyone who needs to keep an event's lines
  together (a group takes 3; a 4th key in the same group is silently dropped by the Init).
