# HUD watch look - adversarial review (2026-10-12)

Read: klhud.c (klu_watch_look, klu_escape_look, klu_dial_base, klu_hand, klu_track_f, klu_dials), klhud_weapon.c (klwd_base, klwd_label, compose), kl_hud.py diff, kl_hud_tab.py diff, kl_hud_watch.py draw_*; looked at dials.png, preview.png and the owner's round picture 0016_149s.jpg. Nothing run (offline review).

VERDICT: ACCEPT WITH FIXES. The look is recognisably a dive watch and the wear is light. But the stroke and the hand direction are wrong against the stated intent, and the default WatchStyle=1 draws garbage on every map that has not been rebaked.

## MUST

1. THE HANDS RUN COUNTER-CLOCKWISE AND THE STROKE IS THE TIME *ELAPSED IN THE MINUTE*, NOT THE TIME LEFT.
   Code: hdeg = left/60*30 (decreasing as time passes), sdeg = (floor(left) % 60) * 6 (decreasing), stroke = arc from sdeg/360 to 1.0 clockwise = (360 - sdeg) = (60 - s_left) * 6 degrees.
   Computed: 5:30 left -> hour 165, sword 180, stroke 180 deg. 2:10 -> 65 / 60, stroke 300. 1:00 -> 30 / 0, stroke 360 (full red ring). 0:40 -> 20 / 240, stroke 120. 0:05 -> 2.5 / 30, stroke 330.
   So the stroke fills up as time runs out, sawtooths every minute (2:00 -> 3:00 left means 0 deg -> 354 deg -> ...: at each whole minute it jumps from ~nothing (59 s) to a full ring (60 s)), and at 1:00 the red ring is full then collapses to a 6 degree sliver one second later. It is the opposite of the escape dial (orange arc length = time left) and of the spec text ("covers the time left"). The summary's "both hands run clockwise" is also false: a countdown whose angle = time left moves counter-clockwise (6 o'clock -> 3 -> 12). On a Rolex-style face that reads as a watch running backwards.
   Fix (the preview model kl_hud_watch.watch_angles / draw_watch has the same bug; fix both): hour angle = 360 - left_min*30 (6 min round starts at 6 o'clock, ends at 12 going via 9), sword angle = (60 - s_left)*6; stroke = hour-hand tip -> 12 while left > 60 s (length = minutes left, drains monotonically over the round), in the last minute sword tip -> 12 (length = seconds left, drains 360 -> 0). No jump at 60 s then: at 1:00 both are 360 -> 0 drain begins.
2. WatchStyle DEFAULTS TO 1 BUT THE OWNER'S INSTALLED MAPS ARE BAKED WITH THE OLD EXTRAS, and the hook cannot tell (it only has handles). Old hook + old level is fine; NEW hook + OLD level: slot 112 (old 'dry' stroke, 256x32) is drawn as a 68 px square "wear" over every face (a smeared horizontal streak stretched square, also on the weapon disc); 115 (old thin ring) acts as the bezel (no pips, no triangle, no batons); 123..125 / 126,185,190 are still 0.23 / 0.12 thick but the hook sizes dab caps for 0.13 / 0.10, so stroke ends do not match. No crash, bounded damage, but it is visible and ugly the first time the new hook meets an unrebaked map. Do one of: ship the new hook with WatchStyle=0 in the owner's ini until the five (seven) maps are rebaked with --watch 1; or let kl_hud_tab write a [HUD] WatchStyle line / a marker file beside the archive and have the hook read it; or give the baked slot a size the hook can read (e.g. check the texture size of 112: 256x32 old vs 128x128 new) if the .TEX record is reachable from the handle.
   Mirror case: NEW level + OLD hook: 114 = worn disc at 69 px / 55 px (fine), 115 = bezel pips drawn as the "track" ring at radius 29 (an extra pip ring inside the old dial, ugly but harmless), 112 users draw the 128x128 wear texture as strike-throughs / rules / scoreboard lines (a smeared scratch pattern instead of a bar). Not garbage-free; do not install the rebaked maps under any older hook.
