# Random map pools (mappool_1027a) - NOT run live

Code: klhook/klmappool.c (included after klslot.c, before klhostopt.c), hooks in klslot.c kls_map (one line) and klhostopt.c (wire + key).
Icons: tools/kl_mappool.py (build), staged in `<DM>\KL_PortTools\build\mappool_1027\` with INSTALL_dm/dd/mix.bat and UNDO.bat.

## Keys
`[MapPool] Enable=0 / Pool=0 (0 off, 1 Full Dead Men, 2 Full Dog Days, 3 Mix) / Apply=0 / Seed=0 / Log=1`; `[HostOpts] KeyPool=0x2D` (Insert cycles the pool, host only).
Needs `[HostOpts] Enable=1` (it carries the pool). Mod-settings row: tools/kl_mod_options.py `mappool` ("recommended off until benched").

## How it works
- Pool = entries (slot, page, folder) from the loaded [Redirect]/[Redirect.N] rules; DM* folders = Dead Men, DD* folders + stock levels = Dog Days.
- Draw = seeded permutation (splitmix64 Fisher-Yates); each load takes the first UNUSED entry of the slot being loaded; all used -> new cycle. No repeat until the pool is spent.
- Sync: klx_opts / UDP 27413 string gained `p<pool>q<seed hex>` (old clients stop before it). Host makes one seed per session (or `Seed=`). Clients apply the host's pool in memory only; no per-round message.
- Slot: map folders are slot-bound (Fxx_Main.*), and the game replicates only the slot index. Apply=0: the draw chooses among the loaded slot's maps only. Apply=1 (GUESS): the host in the lobby (sm state 0xd) sets the slot of the next entry with the stock selector's own calls: sm vtbl+0x28(slot), 0x7163e0, 0x4b5fc0 (commit/replicate), store MP_SelectedLevel (0xb6d6e4) = menu index (inverse of 0x746570: 0,1,2,3,6,4,5,7,8), 0x549e80.
- Icons: static. The lobby picture is a toggler over the 9 slot pictures indexed by the replicated slot; no safe live swap found. kl_mappool.py makes one grid-of-every-map picture per pool, used for all 9 slots, and sets the 9 titles to the pool label. Install the set that matches the host's pool; UNDO restores the first backup (`*.before-1027mappool`, never overwritten).

## Bench

3. Play more rounds than maps: `new cycle` appears only after the pool is spent. Then try Apply=1.

Changes wanted in peer-owned files: none required (klhostopt.c is edited here only for the wire + key).

## Live lobby overlay (mappool_ov_1027) - BUILT, NOT RUN
Code: klhook/klmappool_ov.c (+ pure rules klmappool_ov.h, off-game test klmappool_ov_test.c), 3 lines in klfps.c, 2 calls in klhostopt.c, 1 include in klhook.c. Image tool: `python tools/kl_mappool.py thumbs` (also part of `build`).
Keys (all default off): `[MapPool] Overlay=0` (Mod settings row `mappoolov`, "recommended off until benched"), `OverlayDir=` (folder of the .kmi files; empty = names only), `OverlayX=2 / OverlayY=74` (panel top-left, % of screen), `OverlayScale=100`, `OverlayCols=8`, `OverlayStates=0x2000` (bit mask of session states, bit n = state n), `OverlayNames=1`. Needs `Enable=1`, a pool (host Insert / ini) and `[FrameLimit] Enable=1`.
What it draws (lobby only): pool label (FULL DEAD MEN / FULL DOG DAYS / MIX, coloured bar), `played / total`, then one thumbnail per map of the pool IN PLAY ORDER (the seeded permutation): next map gold frame + NEXT badge, played maps dimmed, name under each thumbnail; a missing image = dark card with the name. All played = nothing dimmed (new cycle).
How the existing draw paths were judged: the HUD path (klhud*.c, klu_pic) borrows the HUD clock element's sprites and cannot draw before session state 0x19, and only shows the game's own sprite handles; the shop page II (klshoppage.c) swaps the game's own picture rows (data writes), which cannot show N foreign thumbnails. So the overlay uses plain Direct3D 9 at Present, read-only towards the game (no .text/.rdata patch, no new vtable write): klfps.c's existing Present wrappers (device slot 17 and swap chain slot 3, depth 0 only) call `klmpo_present(dev)` before the real Present; klfps_createdev stores the device. Per frame (only while the overlay is up): CreateStateBlock(ALL) captured, render target saved, back buffer set, BeginScene, fixed-function pre-transformed quads (FVF 0x144, DrawPrimitiveUP, shaders NULL, alpha blend), EndScene, render target and state block restored. Textures are D3DPOOL_MANAGED A8R8G8B8; text is GDI-rendered (gdi32 looked up at run time) into alpha textures. The draw is in `__try`: an exception disables the overlay for the session (log line).
Data: `kmpo_snap()` runs on the GAME thread from klho_tick (host after kmp_tick, client after the pool is applied), every 100 ms: reads sm state (`[0x168e598]+0x70`), and in a shown state calls kmp_ready() and copies kmp.order / used / names into a double buffer; the render thread reads it, ignores one older than 1.5 s. Host and client show the same (pool + seed are the host's; `used` is advanced by every peer's own load).
Images: `<work>\build\mappool_1027\overlay\<map>.kmi` (21 files now: DD01..DD10, DM01, DM01B, DM02, DM03, DM03A, DM05A, DM06, DM06B, DM07, DM09, DM11B; stock levels would be `stock_F03.kmi`) = `KMI1`, u32 w, u32 h, w*h*4 bytes BGRA, 128 x 72, made from the same pictures as the static lobby grid. Set `OverlayDir=` to that folder in KLHook.ini (`overlay_ini.txt` has the lines).
Off-game test: `cl /nologo /W4 /D_CRT_SECURE_NO_WARNINGS klmappool_ov_test.c` (28 checks: next/played states, spent cycle, grid, file names, state gate, placement).
GUESSES (marked in the code header): the lobby is session state 0xd (the log prints every state change while a pool is on: `mappool: overlay: session state N (SHOWN|hidden ...)`, so set OverlayStates from the first run, no rebuild); BeginScene works at Present time and the render target there is the back buffer (else nothing is drawn, state still restored); the default panel position does not hide something important; the device is plain D3D9 (MANAGED pool legal); D3D9 vtable indices are the public order. Not covered: the pick screen with the picture toggler is still the static icon set; ReShade/Steam overlay ordering (we draw below both, before the real Present).
Bench: Enable=1 Pool=3 Overlay=1 OverlayDir=..., host a lobby: log `mappool: overlay ON`, `session state 13 (SHOWN`, `FIRST draw`; panel visible; play one round: the first thumbnail dims, the next gets the frame. If `overlay DISABLED: exception` appears, send the log.
