# Review of klhook/klhud_names.c + re/hud_names.md (2026-10-12)

Verdict: ACCEPT WITH FIXES. The list half is a pure read and sound. The tag half has two defects that must be fixed before any run (a key name clash and a missing level gate) and rests on one unproven guess (what draws the tag). Nothing was run. Read statically: the two files, klcrew.c (klw_who_now, klw_source, klw_level_tick, klw_rename), klbot.c klb_read, klhud.c klu_compose / klu_tick / klu_inii, klhook.c includes / init / tick order, kl2.exe bytes at 0x83e2e0, 0x469250 and 0x841e50.

## MUST

**M1. `[HUD] Tags` is already a key of klhud.c with another meaning.** klhud.c:1280 reads `klu.tags = klu_inii("Tags", 1, 0, 1)` and uses it at line 893 to append "  TRAITOR" to the own row. klhud_names.c:221 reads the same key as 0/1/2 (initials / full name). Setting `Tags=0` to keep the game's tags also removes the TRAITOR text, and `Tags=1` (the Draft default) is read by both parts. `Tags=2` is clamped to 1 by klhud.c. Fix: rename the new key (for example `NameTags`) in code, note and live check N1. `Names` and `OwnName` are not used by klhud.c; the grep shows no clash.

**M2. `klnm_tick` writes game data on any Arcade level, including the stock ones.** klcrew.c gates its writes (klw_level_tick: `klx_on`, `klx_level_verdict(scene) == 2`, state 0x12..0x19, a "settle" time). klhud_names.c has none of this: `klnm_tick` checks only `klnm.on/tags`, `klh_exe_ok`, `klw.names`, and klw_who_now (Arcade + ZGameRulesHeist + wardrobe). On stock Subway or any stock FA level with `[HUD] Draft=1` the hook would rename the AI records, which rule 1 forbids ("nothing on a stock level unless the owner's parts already act there"). On a stock level there is also the Steam write guard to think of: stock names would change on the page that goes to the stock board. Fix: at the top of `klnm_tick` use the same gate as klbot.c `klb_level(why) == 1` (klbot.c, just under klb_read; it is the section-0 gate every gameplay part uses), or klcrew's verdict test. The list (`klnm_name`) already inherits klu_tick's `allowed` test (`klu.stock || non-stock`), so only the writer needs it.

## SHOULD

**S1. Write only when the round is settled.** klcrew waits for state 0x12..0x19 and for the crew signature to stand still for `settle` ms before it touches anything. `klnm_write` reads `[[at]+8]`; if the block's string is still empty (`s[0] == 0`) it sets `cur = "?"` and calls the rename anyway, on a record the game may still be building (the `st == 0` and `inuse` tests do not prove the client block is complete). Require state 0x12..0x19 (klb_read gives `s.state`) and a non-empty current string, or reuse klcrew's settle test.

**S2. The remembered stock name can become our own text.** `q->stock` is read once, when a new `(at, actor)` is seen. If the actor pointer of a slot changes while the record string still holds our initials (an AI replaced in the same slot, a fed respawn with `[Fed] Bots`, a second round with the same rules object), `stock` becomes "K"; the list then shows "K" for a bot with no known character, and the initials of "K" are "K". The struct has an unused `tagged[48]` field that suggests the idea was dropped half done. Fix: when the current string equals the initials/name this part wrote (`q->ini` or `q->chr`, or `tagged`), keep the old `stock` and do not re-read it.

**S3. Round change.** The re-seeding assumes the rules object changes each round ("Second round: the lines appear again, because the rules object changes", note section 7). klcrew.c does not assume that: it also resets on `state >= 0x1f` then back into the round window (`klw_r.left`, `fresh`). If the object is reused, `tries` stays at 3 after the game resets the name at the next round and the tag is never rewritten. Reset `tries/told` on the same state edge.

**S4. `Names=0, Tags=1` shows initials in the crew list.** With the list off, `klnm_name` returns 0, so klu_compose reads the record string, which now holds the initials. State it in the note or force Names on whenever Tags is on.

**S5. The list entries of departed members stay `used`.** `klnm_refresh` only marks and never clears a record that dropped out of `w.m`; it takes part in the uniqueness pass until the rules object changes. The effect is a two-letter tag that could be one letter. Clear `used` for records not seen this refresh.

**S6. Threading.** `klnm_refresh` mutates the static table and can be called from `klnm_tick` before the `game_thread` test (the fallback thread, which is when the main loop does not run) and from klu_compose (game thread only, klu_tick returns for `!game_thread`). Two threads can meet in the `memset` on a rules change. Move the `game_thread` test above `klnm_refresh` in `klnm_tick`; the list reader is then single-threaded.

## NOTE

- **N1 (the one big guess, agreed).** The element that draws "Tommy / $0" over a bot is not identified. The worker's exclusions (ZPlayerNameDisplay draws only 'Kane'/'Lynch', player list, kill feed) are plausible. If the tag text is cached at actor creation, `Tags` does nothing visible. The failure mode is safe: the log says written, the picture says stock. The tag half should not be promised to the owner before N1.
- **Verified in kl2.exe.** 0x83e2e0 starts `56 8b f1 8b 4c 24 08 8d 44 24 08 50 51 8b ce` and 0x469250 starts `6a ff 68 98 be ad 00 64 a1 00 00 00` — both equal the byte tables in the file and in klcrew.c. 0x469250 is `ret 0xc` and takes the string by value (`[esp+0x14]` is the first stack argument after the SEH prologue = `t.b`), then calls 0x694bc0 with `this = block + 8` and frees a returned pointer via 0x6ad680. That agrees with the call shape (fastcall, ecx = block, three stack dwords) and with "the game takes ownership". 0x83e2e0 is a `ret 4` thiscall; `edx = 0` is ignored. 0x841e50 does `cmp [ecx+0x354]` against the index: record stride 0x7c, +0x10 status, +0x79 flags, `[rec]` the client block, `[blk+8]` the string triple {begin, end, cap}: all as klcrew.c and klb_read use them. No hook buffer pointer is left in a game object: `want` is copied into the game's heap by 0x83e2e0 and the local `t` is only passed by value.
- **Same index as the list.** `klb_read` and `klw_who_now` both use `recs + 0x7c * i`, `inuse[i] == 0`, human = first record without flag 1; `klnm_name` matches by address, so the index agrees. klw_who_now does not exclude the session sub-mode 2/3 that klb_read excludes; harmless because klnm_name is reached only through klu_compose.
- **Initials.** The pure code matches its table (checked by hand: Pierre/Parker/Kane -> PI, PA, K; Mark Lee/Mary Lou -> MARL, MARL2; Tommy x3 -> TOM, TOM2, TOM3). UTF-8: continuation bytes are copied whole, output stays at most 7 bytes; a stray continuation byte at the start is copied alone (a broken character, not a crash). Buffers: `ini[32][8]`, `nm[32]`, `unique` limit 64: no overflow. The human is excluded, so a bot never competes with the human's tag.

The kill feed, round-over page and "Killed by" show initials (already named in the note). The leaderboard path was not read; not a risk with M2.
